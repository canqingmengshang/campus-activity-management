# 02 WBS 文档

> 要求：WBS 必须围绕交付物（成果）分解，至少分解到三级。

## 1. 一级交付物
1. 项目管理成果
2. 需求与范围成果
3. 计划编制成果
4. 配置管理成果
5. 协作与实验总结成果

## 2. 二级与三级分解
1. 项目管理成果
   1.1 组织与启动成果
   1.1.1 项目仓库创建与目录初始化
   1.1.2 团队角色分工表
   1.1.3 项目协作约定文档
   1.1.4 项目背景与目标说明文档
   1.2 过程管控成果
   1.2.1 文档版本变更记录
   1.2.2 小组沟通会议记录
   1.2.3 实验过程检查清单

2. 需求与范围成果
   2.1 项目边界成果
   2.1.1 纳入范围说明书
   2.1.2 不纳入范围说明书
   2.1.3 项目范围确认记录
   2.2 角色与功能成果
   2.2.1 系统角色定义文档
   2.2.2 核心功能清单
   2.2.3 功能优先级说明

3. 计划编制成果
   3.1 范围计划成果
   3.1.1 三级WBS完整文档
   3.1.2 WBS分解说明
   3.1.3 WBS评审记录
   3.2 进度计划成果
   3.2.1 关键活动清单
   3.2.2 简化进度计划表

4. 配置管理成果

   4.1.1 配置项清单

   5.1.1 冲突制造与模拟记录

   5.2.2 实验收获与问题清单
   5.2.3 改进措施与建议

## 3. 分解说明
1. 严格成果导向
   所有分解项均为可交付、可检查、可验收的文档或产物，不使用“讨论、编码、修改、联调”等动作类描述。

2. 三级结构可管理
   一级：实验核心管理域；二级：模块成果；三级：最小可执行单元，可直接分配责任人、工期、纳入进度。

3. 贴合实验要求
   覆盖项目启动、范围管理、进度管理、配置管理、协作冲突、实验总结全流程。

4. 可追溯、可审计
   每一个三级交付物均可对应到进度计划活动、配置项、提交记录。

5. 2人协作
   结构清晰、任务均衡，便于项目经理与配置管理员分工完成，无冗余、无遗漏。
